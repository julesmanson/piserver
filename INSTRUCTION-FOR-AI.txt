PiServer Beta 0.1.0 built with Python 3.14.0 hence Pi


Filename: piserver.py (server)
Design Patterns: Singleton — only one server running per session.
Contents: Server code as Python.
Capabilities: Minimalist HTTP server with config-driven routes, built-in logging, MIME whitelist, and security measures.
Logging: Built directly into piserver.py. No external logger script. On first write to a log file, the file and any parent directories are auto-created.
Log API: Accepts POST {filename, relative_path, content}. Appends content to the resolved file. GET and DELETE also supported via filename and relative_path query params.
Security: Auth token (Bearer), rate limiting per IP (fixed 60s window), content length cap, log injection prevention (strips \r). All values configurable in pi-config.json.
MIME Whitelist: Config-driven. enabled: true serves only explicitly listed file extensions with their declared Content-Type. enabled: false serves all.
Routes: All route paths are config-driven via pi-config.json. Nothing is hardcoded in piserver.py.
Path Traversal: All log and static file operations are resolved and checked against BASE_DIR before serving or writing.
Shutdown Route: Localhost only (127.0.0.1 / ::1). Triggered by second double-click on piserver.py.
START SERVER: Double-click piserver.py.
STOP SERVER: Double-click piserver.py again. Alerts user before shutting down.


Filename: clientside-logging.js (client-side logger)
Design Patterns: ES module singleton — auto-activates on import, persistent for page lifetime.
Loading: Plug-and-play. Drop into any project directory. Load via <script type="module"> or import from any JS file. Activates automatically — no manual setup required.
Config: Two exportable config objects at top of file: config_server = { url: "/log", token: "" } and config_events = [ { keyword, filename, relative_path, events[] } ]
Events: Listens for TypeError, ReferenceError, unhandledrejection, RangeError, SyntaxError, AggregateError, URIError, network (resource load failures), securitypolicyviolation.
Routing: Each event type is routed to the matching config_events entry via an internal Map. Empty or missing events array = catch-all for that entry.
Defaults: relative_path missing, empty, or "" defaults to server webroot. events missing, empty, or "" catches all event types.
Payload on Event: POST {filename, relative_path, content} to config_server.url. Fire-and-forget — errors are swallowed, never propagated to the host page.
Auth: If config_server.token is set, sends Authorization: Bearer <token> header on every POST.
Log Format: Each entry is multi-line — one field per line (timestamp, location, message, stack).
Public API: logEvent(content, keyword) — manually log to a specific keyword's file from any page.


Filename: pi-config.json (config)
Contents: All server, route, security, and MIME settings.
Loading: Read by piserver.py once at startup.
Sections: server (host, port, webroot), routes (shutdown, log), security (auth_token, rate_limit_per_minute, max_content_bytes), mime_whitelist (enabled, types).
_readme: Documentation block at top of file. Safe to delete — piserver.py ignores unknown keys.
